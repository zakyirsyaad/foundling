# Rencana implementasi backend Foundling (`packages/db`, `indexer`, `api`)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Worker yang mengindeks event vault ke Postgres dan menjalankan antrean bukti, API HTTP baca-saja yang melayani riwayat ke website, dan image serta Compose untuk VPS.

**Architecture:** Tiga workspace npm baru di samping `web/`. `packages/db` memegang schema Drizzle dan migrasi. `indexer/` adalah satu proses dengan dua loop terpisah: putaran indeks tiap 30 detik dan antrean bukti dengan backoff. `api/` adalah server Hono baca-saja. Chain tetap sumber kebenaran: database hanya riwayat, grafik, dan hasil bukti, dan semuanya bisa dibangun ulang dari chain kecuali bundel bukti.

**Tech Stack:** Node 24, TypeScript 6, Drizzle ORM dan drizzle-kit, `pg`, Hono dengan `@hono/node-server`, zod, Vitest dengan Postgres sungguhan, Docker dan Compose, Caddy.

**Spec:** `docs/WEBSITE.md` §2, §5, §6, §8, §9, §10 (W2, W3, W6), dan §11. Kontrak API yang harus dilayani sudah dipatok di `web/lib/history/schemas.ts`.

**Cakupan.** Rencana ini mengerjakan W2 (schema), W3 (parser, worker, API), dan W6 (antrean bukti), ditambah image, Compose, alert, dan runbook dari §9. Menyewa VPS, DNS, dan deploy dikerjakan lead. Rencana ini hanya menyiapkan berkasnya.

## Global Constraints

- Workspace npm: `packages/db`, `indexer`, `api`. `npm ci --ignore-scripts` di semua tempat. Versi persis, minimal 14 hari saat dipasang.
- Jumlah token disimpan sebagai `numeric(78,0)` dan dikirim sebagai string desimal.
- Kunci tabel memakai `vault_id`, karena setiap uji melahirkan vault baru dan nonce mulai dari 1 lagi. API melayani satu vault lewat `ACTIVE_VAULT_ID`.
- `events` hanya ditambah. `cycles` diturunkan dari `events` dan bisa dibangun ulang.
- Database tidak menyimpan rahasia, cookie, analytics, atau data API 1Click.
- API: GET saja, CORS hanya untuk origin website, envelope `{ success, data, error, meta }`, `Content-Type: application/json`, `X-Content-Type-Options: nosniff`, paling banyak 100 baris per halaman, parameter divalidasi zod.
- API memakai role database baca-saja, worker memakai role tulis. Postgres tidak terbuka ke internet.
- Rate limit per IP dari header yang diisi Caddy, dan header itu hanya dipercaya dari jaringan internal Compose. Ditambah batas konkurensi global, `statement_timeout`, dan batas memori serta CPU di Compose.
- VPS: hanya port 22, 80, dan 443 terbuka. Rahasia hanya di `.env` VPS.
- Worker tidak memegang kunci apa pun, termasuk kunci NEAR AI.
- Cakupan tes minimal 80% di `indexer/` dan `api/`. `npm audit --audit-level=high` sudah berjalan di job `Web` untuk seluruh workspace.
- Kerja di cabang dan PR. Commit memakai `123721842+zakyirsyaad@users.noreply.github.com`.

## Review Focus

1. Satu transaksi punya beberapa receipt, dan sebagian gagal. Event dari receipt yang gagal atau dari kontrak lain (misalnya token USDC) tidak boleh masuk, tapi event sah dari receipt sukses di transaksi yang sama harus masuk. Tes ada di Task 3.
2. Worker mati di tengah putaran, lalu dua instance hidup saat redeploy. Event tidak boleh dobel dan posisi tidak boleh maju melewati event yang belum tersimpan. Tes ada di Task 5.
3. `decision` tiba lewat yield beberapa blok setelah `cycle_started`, di transaksi lain. Siklus harus tetap utuh, dan antrean bukti harus mengambilnya. Tes ada di Task 5.
4. Klien API mengirim `limit=1000`, `cursor` yang dirakit sendiri, atau nonce negatif. API harus menjawab 400 dengan envelope, bukan 500 atau seluruh tabel. Tes ada di Task 6.
5. `fetch_proof.py` atau `recheck_obs.py` macet atau keluar dengan kode 2 berulang kali. Antrean bukti tidak boleh menahan putaran indeks atau heartbeat, dan harus berhenti di status akhir setelah 24 jam. Tes ada di Task 7.

```ts
export interface Tally { pass: number; skip: number; fail: number; state: "queued" | "running" | "done" | "failed_to_build" }
export function parseSummary(stdout: string): { pass: number; skip: number; fail: number } | null; // baris "SUMMARY pass=N skip=N fail=N"
export function replayResult(stdout: string): "pass" | "fail" | "skip" | null;              // baris PASS/SKIP/FAIL yang namanya berakhir " replay"

```

Aturan dari WEBSITE §5 antrean bukti:
1. Ambil satu baris `proofs` yang `next_attempt_at ≤ now`.
2. Bila bundel belum ada, jalankan `python3 tools/fetch_proof.py --chain <c> --vault <v> --collateral-bin <foundling-verify> --out <tmp> [--rpc <arsip>…] <trigger_tx>`. Simpan bundel mentah dan `approved_measurements` dari dalamnya. Exit 2 berarti sumber tidak terbaca: coba lagi dengan backoff.
3. Jalankan `foundling-verify check <tmp>` dan baca tally dari `SUMMARY`, karena exit code tetap 0 walau ada `skip`. Bila `SUMMARY` tidak ada atau proses timeout, hasilnya `failed_to_build` setelah 24 jam.
4. `obs_source = rehearsal` mencatat obs `{ pass: 0, skip: 1, fail: 0, state: "done" }` tanpa menjalankan alat. Bila `live`, jalankan `python3 tools/recheck_obs.py <tmp>`: exit 1 berarti `fail` tercatat dan selesai, exit 2 berarti backoff sampai 24 jam lalu dicatat `skip`.
5. Saat event `revealed` tersimpan, baca view `revealed` dan `revealed_salt`, isi `bundle.opening = { params, salt }`, lalu jalankan hanya `foundling-verify` ulang. Hanya tally verifier dan `replay` yang ditimpa. Recheck obs tidak dijalankan ulang.
